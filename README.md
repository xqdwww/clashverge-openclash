# clashverge-openclash

A safe, testable local CLI for converting supported Clash configurations into
OpenClash-ready configurations.

The tool reads and writes local YAML files only. It does not contact a router,
download subscriptions, run health checks, execute commands, or make network
requests. Existing output is refused unless `--force` is supplied, and written
files use atomic replacement with owner-only permissions where supported.

## Supported v0.1.0 subset

This release intentionally supports a small, documented subset:

- Inline `proxies` with unique names (proxy fields are passed through)
- Optional `type: select` groups containing inline proxies, other select
  groups, `DIRECT`, or `REJECT`
- Comma-separated rules whose targets resolve to a proxy, group, `DIRECT`, or
  `REJECT`
- Top-level keys: `port`, `socks-port`, `mixed-port`, `allow-lan`, `mode`,
  `log-level`, `ipv6`, `dns`, `proxies`, `proxy-groups`, and `rules`

If no group exists, conversion creates one manual `OPENCLASH` select group. If
no final `MATCH` exists, conversion appends one targeting that group (or the
validated `--default-target`). Output is set to `mode: rule`.

Unknown top-level keys, provider-based configuration, non-select groups,
duplicate names, unresolved references, group cycles, multiple `MATCH` rules,
or a non-final `MATCH` are rejected instead of being silently rewritten.

## Installation

From an unpacked source checkout:

```bash
python -m pip install .
```

## Usage

```bash
clashverge-openclash --help

clashverge-openclash convert \
  --input source.yaml \
  --output openclash.yaml

clashverge-openclash convert \
  --input source.yaml \
  --output openclash.yaml \
  --dry-run

clashverge-openclash convert \
  --input source.yaml \
  --output openclash.yaml \
  --force

clashverge-openclash validate openclash.yaml --type target
```

The CLI exits `0` on success, `1` for rejected input or file-processing errors,
and `2` for command-line usage errors generated by `argparse`.

## Security and data handling

Proxy configurations normally contain sensitive server and credential fields.
The converter does not print those values, but the output remains sensitive.
Keep real configurations out of issues, commits, fixtures, and logs. YAML is
loaded with a safe loader, duplicate keys are rejected, and input size and YAML
alias counts are bounded.

Repository fixtures use RFC 5737 TEST-NET addresses and synthetic credentials.

## Scope and compatibility

“OpenClash-ready” means the generated YAML satisfies this project's documented
structural subset. It is not a guarantee of compatibility with every Clash,
Mihomo, OpenClash, proxy-protocol, or plugin version. Review the diff and test
the result in your own environment before use.

This project is not an official OpenClash, Mihomo, or Clash project. It is not a
router-management platform, OpenClash control center, subscription service, or
remote deployment tool.

The interoperable field and rule shapes are based on the public
[Mihomo configuration documentation](https://wiki.metacubex.one/en/config/)
and its public pages for
[proxy groups](https://wiki.metacubex.one/en/config/proxy-groups/) and
[rules](https://wiki.metacubex.one/en/config/rules/). No upstream implementation
code is vendored or copied.
